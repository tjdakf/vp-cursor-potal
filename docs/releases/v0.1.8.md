# vp-cursor-portal v0.1.8

Patch release that prevents duplicate app launches from competing for cursor control, global hotkeys, and configuration writes.

## Downloads

| Asset | Use |
|---|---|
| [vp-cursor-portal-setup.exe](https://github.com/tjdakf/vp-cursor-portal/releases/download/v0.1.8/vp-cursor-portal-setup.exe) | Windows x64 installer under `Program Files` |
| [vp-cursor-portal-win-x64.zip](https://github.com/tjdakf/vp-cursor-portal/releases/download/v0.1.8/vp-cursor-portal-win-x64.zip) | Self-contained portable folder; extract the entire ZIP and run `vp-cursor-portal.exe` |

Neither download requires a separate .NET runtime installation.

## Fixes

- Allows only one instance per Windows user session, including copies in different installation or portable folders.
- Rejects duplicate launches before cursor control, monitor watching, hotkeys, or configuration access are initialized.
- Requests that the existing window reopen when the executable is launched again, including from the tray or a minimized state.
- Retains open-window requests received during startup and cancels a pending startup-to-tray hide when restoring the window.
- Preserves maximized window state when reopening from the tray.
- Releases ownership on exit and accepts abandoned ownership after an unexpected exit.
- Shows an already-running message if the existing instance cannot receive the request; the duplicate still exits.

## Upgrade

1. Stop routing and choose **Exit** from every running copy's system-tray menu. **X** only hides the window. Older versions do not have the duplicate-launch guard, so exit them before starting this version.
2. Back up `%AppData%\vp-cursor-portal\config.json` if it contains field settings.
3. Run the new installer, or extract the ZIP to a fresh folder and update shortcuts to the new executable. Keep the AppData configuration in place.
4. If moving a portable copy with Windows startup enabled, disable that option before moving and enable it again from the new location.
5. Confirm `0.1.8` in **About**, then check saved profiles/layouts and emergency unlock before enabling routing.

## Compatibility

- Existing configuration files, layouts, profiles, aliases, and saved display history remain compatible. No configuration schema migration is introduced.
- Cursor routing rules and H2 protocol behavior are unchanged.
- Installed and portable copies share the same per-user AppData configuration.
- The single-instance guard is scoped to a Windows user session; it does not coordinate separate Windows sessions.

## Validation

- Release-configuration solution cross-build passed on macOS with .NET 10.
- Existing Core tests (26) and H2 tests (11) passed locally.
- Four portable service checks passed through a temporary source-linked test harness: duplicate rejection and release, abandoned ownership recovery, disconnected-client recovery, and notification timeout.
- Six service tests are included in the Windows App test suite, including activation notification and startup connection waiting. The Windows Build workflow runs the full suite and builds both release assets before uploading them.
- Manual Windows window/tray/foreground behavior, installer operation, and real H2/multi-monitor field behavior have not been verified for this release. Automated service tests do not prove visible window activation.

## Known Limitations

- Windows can restrict foreground focus. If reopening fails, use **Open** on the existing tray icon. Different privilege contexts may prevent the activation message from being delivered.
- The installer and executable are not code-signed, so Microsoft Defender SmartScreen may show an unknown publisher warning.
