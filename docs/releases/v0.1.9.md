## Getting This Version

Install `v0.1.9` manually once. Previous versions do not contain the updater.

1. Stop routing and choose **Exit** from the existing app's tray menu. The window's **X** button only hides it.
2. Run the new installer. Keep `%AppData%\vp-cursor-portal\config.json` in place; no uninstall is required.
3. Confirm `0.1.9` in **About**. Saved devices, layouts, profiles, aliases, and safety settings remain available.

## Future Updates From Settings

1. Open **Settings → Check for Updates** to see a newer version and its release notes.
2. Click **Install Update**. The installer is downloaded and its expected size and SHA-256 checksum are checked.
3. The app finishes pending configuration writes, saves the current settings, stops routing, and exits.
4. Approve the Windows permission prompt. Installation proceeds with a progress window, then the helper reopens the app as its original user.
5. Select the desired profile to resume routing. Routing starts disabled after restart, just as on a normal launch.

Optional startup checking is off by default. It checks only; updates are never installed without clicking **Install Update**.

## Preservation And Failure Handling

- No configuration schema migration or separate backup file is introduced.
- Configuration saves write the complete new document to a temporary file before replacing `config.json`, preventing an incomplete write from truncating the previous file.
- Download/checksum failures and download cancellation leave the current app open.
- Invalid settings or save errors prevent installation from starting.
- The update helper waits for the original process to exit and checks the installer checksum again before executing it.
- Cancelling the Windows permission prompt is reported and the app is reopened. Other installation failures are reported and a relaunch is attempted; automatic binary rollback is not implemented.
- The update does not force-close other applications or automatically reboot Windows. A required reboot is reported.
- Update preferences are stored in `%AppData%\vp-cursor-portal\update-settings.json`. Downloads and installation/error logs use `%LocalAppData%\vp-cursor-portal\updates`; folders older than seven days are cleaned at startup.

## Validation

- Automated tests cover version comparison, release asset validation, size/checksum mismatch, network failures, cancellation, UI command state, update preferences, final configuration saving, and cancelled configuration writes.
- The Windows workflow builds/tests all projects and publishes a standalone helper before packaging the installer and ZIP.
- An isolated Windows installer smoke test checks install/reinstall configuration preservation, parent-process handoff, retained device settings, installed version, and a successful app relaunch request.
- Visible WPF interaction, real UAC consent/cancellation, and H2/multi-monitor field behavior still require manual validation on a Windows test PC. The installer smoke test does not simulate all of these user interactions.

## Compatibility And Limitations

- Existing cursor routing rules, H2 behavior, and the `v0.1.8` single-instance guard are preserved.
- Automatic installation requires the running directory to match the registered installer location. Portable/development copies cannot invoke it.
- Internet access to GitHub is required for release checks and downloads. Offline operation of existing app features continues normally.
- The installer and executable remain unsigned. Checksum validation verifies the downloaded release asset; it does not add a code-signing certificate or remove SmartScreen warnings.
